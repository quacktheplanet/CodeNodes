# CodeNodes MCP server

Lets an assistant write GPU code, build real Blender geometry with it, and **look at the result** —
without giving it the ability to run arbitrary code in Blender.

```
assistant ⇄ MCP (stdio) ⇄ codenodes-mcp ⇄ localhost socket ⇄ CodeNodes add-on in Blender
```

## Setting it up

1. **Install the add-on** in Blender (the extension zip, via Edit › Preferences › Get
   Extensions › Install from Disk). Its link starts by itself whenever Blender opens: nothing to
   press, nothing to copy.
2. **Give Claude the plugin** (the easy way):

   ```bash
   claude plugin marketplace add quacktheplanet/CodeNodes
   claude plugin install codenodes@codenodes
   ```

   Or point any MCP client at the server directly. It's standard library only, so any Python 3.10+
   runs it:

   ```bash
   claude mcp add codenodes -- python path/to/CodeNodes/mcp/run_server.py
   ```

   (`pip install -e path/to/CodeNodes/mcp` also gives a `codenodes-mcp` command, and
   `python -m codenodes_mcp` works from this folder.)

Each Blender running CodeNodes registers itself in `~/.codenodes/instances/<pid>.json` (port and
token), and the server talks to the newest one; `status` lists them all and `use_blender(port)`
switches. The first Blender takes port 9877, the next 9878, and so on. `CODENODES_HOME` moves that
folder; `CODENODES_PORT` / `CODENODES_TOKEN` still override. Older CodeNodes without the registry are
found on 9877 with the token from Blender's config folder.

## The tools

| tool | what it does |
|---|---|
| `guide` | how to write each kind of code, the GLSL helpers, a template for each |
| `make` | build a `mesh`, `shape`, `particles` or `volume` from code |
| `set_params`, `get_code`, `scene` | adjust sliders, read back the code, see what exists |
| `look_at`, `light`, `set_frame` | aim the camera, light the scene, move the timeline |
| `render`, `viewport` | **a picture back**, so the assistant can judge its own work |
| `bake` | write the animation to disk so it renders anywhere |
| `material`, `collect`, `curve` | materials by name, collections, curves to build along |
| `nodes_help`, `nodes_library`, `nodes_use`, `nodes_set_inputs` | ready-made Geometry Nodes capabilities |
| `nodes_find`, `nodes_describe`, `nodes_list`, `nodes_read`, `nodes_write`, `nodes_apply`, `nodes_edit`, `nodes_explain`, `nodes_check` | read, build, edit and explain any node tree |
| `web_page` | the scene as an interactive web page with sliders |
| `web_shape` | a Code Shape as a page that rebuilds it live in the browser, at any slider value |
| `code_node` | geometry made by code as a node inside Geometry Nodes, its sliders as node inputs (what Add › Mesh › Code Mesh makes) |
| `remove`, `status`, `use_blender` | delete an object; check the link and list open Blenders; switch between them |

## What it cannot do

There is no `execute_code` tool, and no way to add one from the client: the add-on answers only the
names in its own table (`codenodes/server.py`, `dispatch_table`). A client that asks for `exec`,
`eval` or anything else gets "no tool named …".

Other deliberate limits:

- **Localhost only.** The socket binds `127.0.0.1`; it is never reachable from the network.
- **A token is required.** Generated by Blender, 32 random bytes, compared in constant time. It's
  written where the MCP server reads it, so nobody has to copy it.
- **On by default, easy to turn off.** It starts when the add-on is enabled (not in background
  `-b` Blender), and stops with Edit › Preferences › Add-ons › CodeNodes › *Let assistants
  connect*, when the add-on is disabled, or when Blender quits.
- **Messages are capped** at 4 MiB in, 24 MiB for an image out.
- **No telemetry.** Nothing leaves your machine.

## How it works inside Blender

Blender's Python is not thread-safe, so there is no worker thread. The listening socket is
non-blocking and every step — accept, read, run the tool, reply — happens inside a
`bpy.app.timers` callback, which already runs on the main thread. Polling is 50 ms while busy and
backs off to 500 ms when idle. (Blender's own Lab MCP uses the same approach; this is an
independent implementation of that idea.)
